모형 데모 · 설계 가이드 · 우리 기기(ESP32 + P10 LED) 기준

중간평가용 “작동하는 실물”을 탁상 모형으로 구현하는 방법입니다. 실제 센서(LD2450 레이더)가 보행자를 감지하면 P10 LED에 ✕가 뜨고, 메타버스 화면의 가상 보행자도 같은 방식으로 실제 LED를 바꿉니다.

0무엇을 보여줘야 하나
  • 보행자를 감지하면 1초 이내에 LED가 ✕ (빨강, 우회전 불가)로 바뀜
  • 보행자가 사라지면 1초 유지 후 → (초록, 우회전 가능)으로 복귀 — 안전 지연
  • 현실 레이더 · 메타버스 가상 보행자 중 어느 쪽에서 신호가 와도 같은 LED 결과를 냄
  • 위 동작을 반복 측정한 데이터 표(감지율·오감지율·반응시간)로 증명 (7번 항목)
1시스템 구성
센서 유닛 → (블루투스) → LED 유닛 ⇄ (USB) → 노트북 메타버스. 메타버스가 끊겨도 LED 유닛은 자체 센서로 계속 동작.

3센서 배치 & 척도

설치 모퉁이 기둥(횡단보도 진입부 쪽)에 레이더를 고정하고, 횡단보도와 진입로가 함께 보이도록 살짝 북쪽으로 조준합니다.

블루투스 거리가 멀면 센서 유닛과 LED 유닛을 가깝게 두세요.

✕ 빨강 · 우회전 불가

보행자가 없고 안전 지연이 끝난 상태.

설계 원칙 · 판단이 불확실하면 ✕. 모양은 방향 화살표로 그려 보행자 신호와 구분하고, 패널은 운전자 시야 방향에 맞춰 둡니다. 픽셀 순서는 패널 방향에 맞게 보정합니다.
5판단 규칙
  1. 현실 레이더 감지 또는 메타버스 가상 보행자 → ✕ (판단 모드에 따라 다름)
  2. 보행자가 사라져도 1초(holdSec = 1.0) 동안 ✕ 유지 후 → 복귀
  3. 메타버스 신호가 3초 이상 끊기면 자동으로 현실 센서만 사용 (케이블이 빠져도 안전)
  4. 센서 유닛과 블루투스가 끊기면 ✕ 유지 (보행자 안전 우선, 예시 코드 기본값)

7시나리오 & 측정 프로토콜 중간평가 핵심

아래 시나리오를 각 20회 반복하고, 매 회 기대 LED · 실제 LED · 반응시간을 기록합니다.

#시나리오기대 LED측정 목적
①보행자 없음→정상 상태 · 오감지 분모
②보행자가 감지 구역에 접근✕감지율 (진입)
③횡단 중✕감지율 (횡단)
④보행자 이탈✕ → 1초 후 →안전 지연 확인
⑤비보행자 물체 움직임 (공 · 우산)→ 유지오감지율
⑥메타버스 가상 보행자 (META 모드)✕메타버스 → 실제 LED 연동

산출: 감지율 = ②③ 중 ✕ 비율 · 오감지율 = ①⑤ 중 ✕ 비율 · 반응시간 = 감지부터 ✕ 표시까지 (로그 기준). 목표: 감지율 95% · 오감지율 5% · 반응 1초 이내.

8자동 시연 (메타버스 기본 화면)

예전 ‘작동 애니메이션’ 자리를 메타버스 자동 시연 화면이 대신합니다. 파일을 열면 기본으로 재생되며, 우회전 차량 · 보행자 · 신호가 자동으로 움직이고, Right Guard 설치 → 보행자 감지 → ✕ 표시 → 실제 기기 연결 장면을 순서대로 보여 줍니다.

  • 단축키: 1 자동 시연 · 2 직접 운전 · 3 관제 모드 · P 보행자 보내기 · G Right Guard 켜기/끄기 · F 전체 화면
9중간평가 라이브 시연 순서 (약 3~4분)
  • ① 자동 시연 30초로 전체 개념 설명
  • ② 실제 보행자가 감지 구역에 들어옴 → P10 LED가 ✕로 바뀌는 순간 강조
  • ③ 보행자가 빠져나감 → 1초 뒤 → 복귀 (안전 지연)
  • ④ 메타버스에서 ‘보행자 보내기’ → 실제 LED도 ✕
  • ⑤ 마지막에 측정 데이터 표로 감지율 · 오감지율 · 반응시간 제시
